# 家計簿アプリ 実装・検証計画

## 正式な参照元

- 機能仕様: https://app.notion.com/p/3db704c9a94380e69310da2a6cb984bf
- デザイン: https://www.figma.com/design/Gkx5ZvfH8wwuvt9hcxxFcE/でざいん?node-id=0-1
- 取得済みデザインの状態は `design-reference/capture-status.md` に記録する。
- OCR はユーザー指定により Google Cloud Document AI Expense Parser。
- TanStack Start / Better Auth / Cloudflare D1 / Drizzle / Workers を維持する。

## 完成条件

環境構築だけでは完了としない。実データで登録・編集・保存・履歴・分析が連動し、ユーザーをまたいだアクセスを拒否することを確認する。

1. メール・パスワード登録、ログイン、ログアウト、保護されたアプリ本体。
2. ホーム、履歴、新規登録、分析、設定をつなぐナビゲーション。
3. 手動収入・支出の登録、編集、削除。履歴の月・日付・カテゴリ・収支種別・店舗・金額フィルタとページング。
4. レシート画像の取得、解析中表示、解析失敗時の再試行・手動移行、商品明細を確認・修正後に確定保存。
5. 原本画像を非公開保存し、本人だけが参照できる。OCR結果を自動確定しない。
6. 商品単位のカテゴリと支払額配賦。初期カテゴリおよびカスタムカテゴリCRUD。カテゴリ削除後の履歴は「その他」に移す。
7. 商品割引、全体割引、ポイント、商品券を区別し、合計と実支払額の整合性を保つ。
8. 類似レシートの重複警告とユーザーによる続行、多重送信防止、競合更新の検出。
9. 月次収支・カテゴリ集計・前月比較・推移・固定費・光熱費分析。
10. 月次支出予算・収入目標、毎月の定期支出、手動管理の銀行・現金・商品券資産。銀行の外部連携は対象外。
11. 保存失敗で入力を失わず、待機状態と復帰手段を表示する。
12. スマートフォンとデスクトップで表示・操作を検証し、Figma参照と照合する。

## 計算上の実装判断

- JPYは安全な整数で扱う。
- 全体割引は仕様の「割引前金額比率」に従って配賦する。商品ごとの残額を上限とし、最大剰余法で端数を調整する。同順位の端数は明細順で決定する。
- ポイント、商品券の順で配賦し、カテゴリ集計用の支払額合計を現金等の実支払額に一致させる。
- 不明なOCR値は推測で埋めない。ユーザーによる補完を必要とする。
- 返品・返金は仕様に沿って元取引の修正・削除で扱う。
